# 实验方案：基于 PT²-LLM 的相似配对 Haar 三值 PTQ

**Problem**：在单卡 RTX 4090 24GB 上复现 PT²-LLM 的 1.58-bit PTQ baseline，并验证“结构相似列配对 + 局部 Haar + 频带三值网格”能否在真实存储预算下改善三值量化。

**Method Thesis**：相似列经过局部 Haar 后，高频差分能量应下降；零中心三值高频网格可更有效地使用零状态，从而降低 activation/Hessian-weighted 量化误差，而不是宣称 Haar 本身增加浮点模型表达能力。

**Date**：2026-08-21

**Compute Constraint**：单卡 RTX 4090 24GB；云端 CPU RAM、磁盘、驱动和网络待连接后审计。

**Upstream evidence**：`KILL_ARGUMENT.md` 将因果链、实际 bit-width 和推理开销列为三个尚未解决的问题。本方案将它们设置为显式决策门。

## Claim Map

| Claim | Why It Matters | Minimum Convincing Evidence | Linked Blocks |
|---|---|---|---|
| C1（主张）相似配对 Haar 能降低三值 PTQ 的 activation-weighted distortion | 决定该方法是否超越“PT² + HBLLM 拼接” | 在相同校准设置下，similarity pairing 相比 random/dissimilar pairing 稳定降低高频能量、提高合理的高频零率、降低 Hessian-weighted error，并最终改善 PPL | B2, B3, B4 |
| C2（支持）收益在相同实际存储预算下仍成立 | 避免通过额外 scale/shift 买精度 | 完整统计 ternary code、scale、shift、pairing metadata、padding 后，在 bit-matched 对照下仍优于 PT² | B4 |
| Anti-claim：收益只来自任意正交变换、额外参数或 SSR 本身 | 这是最强拒稿主线 | PT²、SSR-only、random Haar、adjacent Haar、similarity-paired Haar、band-grid、joint-AGA 的逐级消融 | B2, B4 |

## Paper Storyline

- 主文必须证明：C1 的因果链、C2 的 bit-matched 结果、对 PT² full baseline 的主结果。
- 附录支持：逐层频谱统计、不同 block size、不同 calibration seed、各投影类型的 failure map。
- 暂时删除：多层小波、Daubechies、全局 rotation、混合精度显著列、MoE。这些会模糊主线。
- 不宣称：Haar 增加原始模型表达能力；原坐标系逆变换权重仍是普通三值；未实现 kernel 前不宣称端到端加速。

## 官方 baseline 与 24GB 约束

官方仓库：[XIANGLONGYAN/PT2-LLM](https://github.com/XIANGLONGYAN/PT2-LLM)。当前 README 给出的 full baseline 是 `atq --blocksize 128 --ssr`；依赖固定为 Python 3.10、PyTorch 2.4.0、Transformers 4.44.2。代码逐层将模型移入 GPU，但默认会建立 `nsamples × seqlen × hidden_size` 的 `inps`、`outs`、`fp_inps`，并通过 `FPInputsCache` 缓存多个目标线性层的 FP 输入。因此论文设置 `128 × 2048` 在 24GB 上存在显著 OOM 风险。

执行策略：

1. 先用 TinyLlama 1.1B 或兼容的 Llama 小模型跑通代码与指标。
2. 在 LLaMA-2-7B 上用 `nsamples=8/16, seqlen=512` 做显存剖析。
3. 逐步提升到 `32×1024`、`64×2048`。
4. 若 `128×2048` OOM，先优化 FP input cache（共享 Q/K/V 与 gate/up 的相同输入、按 sequential subset 缓存、必要时 CPU pinned-memory streaming），再运行官方配置。
5. 不依赖 `--minlayer/--maxlayer` 做快速实验，直到确认当前代码实际使用了这些参数；优先添加明确的 layer-range 单元测试。

推荐主模型：

- 开发模型：`TinyLlama/TinyLlama-1.1B-*`（具体可用 checkpoint 在云端核对）。
- 主结果模型：`meta-llama/Llama-2-7b-hf`，需要已获许可的 HF token。
- 若无法获得 LLaMA-2：先用 Qwen 1.5B/3B 兼容模型开发，但不能将其结果直接视为 PT² 论文数值复现。

论文参考锚点（LLaMA-2-7B，WikiText2 calibration，128 samples，2048 tokens，block 128）：full PT² 报告 WikiText2/C4 PPL 约 11.56/24.38；无重排版本约 13.06/27.66。首次复现允许 10% 相对偏差，最终复现目标为 5% 内；超出范围必须先查版本、数据、tokenizer 和保存/加载路径，不能直接进入新方法实验。

## Experiment Blocks

### B1：环境与 PT² baseline 复现

- **Claim tested**：官方实现、数据和评估在 4090 上可信可重复。
- **Why**：没有可信 baseline，任何增益都不可解释。
- **Dataset/task**：WikiText2、C4 perplexity；先不跑 zero-shot QA。
- **Compared systems**：FP16、ternary-init、ATQ without SSR、ATQ + SSR。
- **Metrics**：PPL、quantization time、peak allocated/reserved VRAM、CPU RAM、失败栈、checkpoint size。
- **Setup**：seed 0；block 128；分级增加 `nsamples` 和 `calib_seqlen`。
- **Success criterion**：小模型全流程通过；LLaMA-2-7B full PT² 与论文锚点最终在 5% 相对误差内，或找到并记录可解释的版本差异。
- **Failure interpretation**：若 baseline 无法复现，冻结方法开发，先修复复现链路。
- **Table target**：Reproduction table / engineering appendix。
- **Priority**：MUST-RUN。

### B2：机制诊断——Haar 是否产生可量化的高频

- **Claim tested**：similarity pairing 的高频能量与 activation-weighted residual 低于随机/相邻/反相似配对。
- **Why**：这是整篇工作的最小可证伪核心。
- **Dataset/task**：从 8–16 条 calibration samples 抽取各层 Q/K/V/O、up/gate/down 权重与激活；无需完整模型 PPL 即可先做 block-level 诊断。
- **Compared systems**：identity/no Haar、original-adjacent Haar、random pairing、SSR-order-adjacent Haar、explicit cosine matching、dissimilar matching（负控制）。
- **Metrics**：`E_H/E_total`、高频幅值分位数、ternary zero rate、weight NMSE、`||(C-Q(C))Z||²`、Hessian-weighted error；按 layer type 汇总中位数和分布。
- **Setup**：block 128，normalized Haar；先用共享 ATQ 网格，随后频带网格；所有 pairing 使用同一权重和激活。
- **Success criterion**：similarity matching 相比 random pairing 在多数层（目标 ≥70%）降低高频相对能量，并使 activation-weighted error 中位数至少降低 5%；零率上升必须伴随误差下降，不能只追求更多零。
- **Failure interpretation**：若高频能量或 weighted error 无一致改善，停止主线；不要通过继续叠加 AGA 掩盖机制失败。
- **Figure target**：pairing type → high-frequency energy → weighted error 的因果图。
- **Priority**：MUST-RUN。

### B3：主方法 fake-quant 结果

- **Claim tested**：在 PT² full pipeline 中，similarity-paired Haar + band-aware ATQ 改善端到端 PPL。
- **Why**：block-level 机制必须转化为模型级收益。
- **Dataset/task**：WikiText2/C4 PPL；开发模型先筛选，LLaMA-2-7B 做决定性运行。
- **Compared systems**：PT² full；PT² + adjacent Haar/shared grid；PT² + random Haar/band grid；PT² + SSR-order Haar/band grid；PT² + explicit matching Haar/band grid；最后一个再加 joint AGA。
- **Metrics**：PPL、quantization time、peak VRAM、layerwise weighted error、NaN/Cholesky failure count。
- **Setup**：第一轮 seed 0；候选收敛后只对 baseline 和最佳方法跑 3 个 calibration seeds。
- **Success criterion**：开发模型相对 PT² full 的 PPL 至少改善 5%，且两数据集方向一致；进入论文阶段前，LLaMA-2-7B bit-matched 设置至少有稳定的 3% 相对改善或等价的明显 accuracy gain。
- **Failure interpretation**：只有 weight MSE 改善而 PPL 不改善，说明变换与激活敏感度未对齐；优先检查 joint AGA/配对代价，而不是扩充小波族。
- **Table target**：主结果表。
- **Priority**：MUST-RUN。

### B4：新颖性、简洁性与 bit-matched 消融

- **Claim tested**：收益来自相似配对和频带三值几何，而不是多参数、任意旋转或更高 bit budget。
- **Compared systems**：
  - PT² no SSR / PT² SSR；
  - fixed adjacent / random / dissimilar / similarity matching；
  - shared grid / separate low-high grids；
  - independent AGA / joint 3-parameter AGA；
  - free `mu_H` / constrained `mu_H=0`；
  - equal-group-size / equal-effective-bits。
- **Metrics**：PPL、weighted error、metadata bits/weight、physical packed bits/weight、配对索引摊销。
- **Bit accounting**：block 128 下，理想 ternary code 为 `log2(3)=1.585` bit/weight；PT² 的 FP16 `alpha,mu` 约增加 `32/128=0.25` bit/weight；候选 `alpha_L,mu_L,alpha_H` 增加 `48/128=0.375` bit/weight。必须提供 FP16/FP8 metadata、base-3 packing 与实际对齐后的多种口径。
- **Success criterion**：在相同 effective bits 下仍优于 PT²；若仅 equal-group-size 有提升，应降级主张为 accuracy/storage trade-off。
- **Failure interpretation**：若 bit-matched 增益消失，核心论文主张不成立，但可转为高保真压缩工程方案。
- **Table target**：主文消融 + storage table。
- **Priority**：MUST-RUN。

### B5：因子化推理与 failure analysis

- **Claim tested**：`z=Rx; y=Q(C)z` 的执行不会把收益全部还给 transform、gather 和 affine metadata。
- **Compared systems**：PT² ternary path、dense reconstructed fake-quant、Haar-domain ternary prototype。
- **Metrics**：prefill/decode tokens/s、kernel time、DRAM bytes、transform overhead、gather/cache penalty、峰值显存。
- **Setup**：准确率 gate 通过后才实现；先做 PyTorch/Triton microbenchmark，再决定是否集成 llama.cpp/CUDA。
- **Success criterion**：Haar/gather/affine overhead 相对 ternary GEMM 小于 10%，或端到端仍明显快于 FP16/2-bit reference。
- **Failure interpretation**：若准确率有效但 kernel 不划算，论文必须收窄为 compression/fidelity 方法，不能宣称加速。
- **Figure target**：latency breakdown。
- **Priority**：NICE-TO-HAVE for go/no-go，MUST-RUN for final systems claim。

## 4090 资源预算

- **Must-run GPU budget**：约 23–50 GPUh；实际以 M0/M1 profiling 校准。
- **Turnaround estimate**：单次 TinyLlama run 约 10–40 分钟；LLaMA-2-7B reduced-calibration run 约 0.5–2 小时；`64/128 × 2048` 可能为 1–5 小时或因内存优化而变化。以上仅为排程范围，不作为结果承诺。
- **CPU RAM**：建议至少 64GB；低于 48GB 需要更积极的 streaming/offload。
- **Disk**：建议至少 100GB 可用。避免保存每个 fake-quant checkpoint；只保存 baseline、最佳候选和最终 seeds，其余保留日志与 metrics JSON。
- **Network/data**：需访问 Hugging Face、C4/WikiText2；LLaMA-2 需要许可 token。所有 token/SSH key 仅通过环境或用户指定的安全路径提供，不写入仓库或日志。
- **Human evaluation**：不需要。
- **Biggest bottleneck**：FP activation cache，而非单层权重。

## 实现边界

第一阶段只做可逆 fake-quant：

1. 在 Haar 域量化得到 `C_hat`；
2. 重构 `W_hat = C_hat R` 写回线性层；
3. 用现有 Hugging Face PPL 路径验证准确率。

这不能证明实际三值 kernel 加速，但能最小成本验证算法假设。只有 B2/B3 gate 通过后，才保留 `C_hat` 并实现 `z=Rx; y=C_hat z` 的 factorized inference。

建议代码增量：

- `pt2_llm/haar_pairing.py`：adjacent/random/dissimilar/similarity matching、Haar transform、inverse、统计指标。
- `TernaryQuantizer` 新增 `haar-band-atq`：共享网格与低/高频网格两种模式。
- `GPTQ_SSR.fasterquant`：把 SSR reorder 与 pair matching 解耦；显式返回 pairing/permutation。
- metrics JSON：每层记录 pairing、`hf_energy_ratio`、zero rates、NMSE、weighted error、condition number、peak VRAM。
- 单元测试：Haar 可逆性、`WX == CZ`、permutation inverse、共同/独立网格闭式解、bit accounting。

## 风险与缓解

- **风险：PT² baseline 在 24GB OOM。** 缓解：分级样本/序列长度；共享重复 FP inputs；按 subset 缓存；CPU pinned streaming；每一步记录峰值显存。
- **风险：SSR order 不等价于真正 pair similarity。** 缓解：加入 explicit maximum/greedy matching，并以 random/dissimilar pairing 为控制。
- **风险：Haar 只让零率上升但误差更差。** 缓解：go/no-go 使用 weighted error 和 PPL，不用 zero rate 单独判成功。
- **风险：joint AGA 的小线性系统病态。** 缓解：记录条件数，加入 ridge damping，保留 independent AGA fallback，并报告 fallback 比例。
- **风险：实际 bit-width 超标。** 缓解：从第一轮就输出 storage ledger，主结果必须包含 bit-matched 版本。
- **风险：fake-quant 成功但 kernel 失败。** 缓解：分离 fidelity claim 与 systems claim；未完成 B5 前不宣称端到端加速。
- **风险：模型许可或网络失败。** 缓解：TinyLlama/Qwen 做工程开发，LLaMA-2 仅用于最终可比复现。
